# Open X3D Pro

Open-source replacement for Logitech Gaming Software 5.10 for the Logitech Extreme 3D Pro joystick (`USB\VID_046D&PID_C215`) on Windows 10 22H2 and Windows 11 24H2/25H2 x64. It provides per-axis calibration, deadzones, response curves, inversion, button remapping, hat-as-buttons, a shift layer and per-application profiles applied automatically by a tray agent. It contains no kernel-mode code, so it installs and runs with Secure Boot and Memory Integrity (HVCI) on, unlike LGS 5.10's 2010-era kernel filter.

**Status: pre-alpha.** Nothing here is ready for daily use yet.

## Architecture

- `driver/`: UMDF 2 HID minidriver (`openx3d.dll`) that replaces inbox `hidusb` as function driver of the stick; user mode only.
- It reads the 7-byte interrupt report, runs the axis/button pipeline inline and republishes two HID collections.
- Collection 1 is a joystick (4 × 16-bit axes, hat, 32 buttons) that games, joy.cpl and DirectInput see.
- Collection 2 is a vendor channel: raw input reports plus feature reports to load and query the active config.
- The config is a 240-byte CRC-checked blob, persisted in the device registry key and reloaded at device start.
- `core/`: Rust crate `x3d-core` with the config types, reference pipeline, blob compiler and test vector generator.
- Driver C and Rust pipelines agree bit-for-bit, checked against shared vectors in `core/testdata/vectors.json`.
- `app/`: Tauri v2 tray agent (Rust backend, React + TypeScript UI) that edits profiles and pushes them to the driver.
- Profiles switch on the foreground or running executable; the NSIS installer adds the driver via `pnputil`.
- Interfaces and layout: [docs/CONTRACT.md](docs/CONTRACT.md). Background and design rationale: [docs/research.md](docs/research.md).

## Building

Prerequisites:

- Rust 1.98.1 (pinned in `rust-toolchain.toml`, with rustfmt and clippy)
- Node.js 20
- Windows Driver Kit: only needed to build the driver, which happens in CI on GitHub's Windows runners. Everything else builds and tests on Linux.

Dev commands:

```sh
cargo test --workspace                 # core + app backend (Win32 code is stubbed off Windows)
cd app && npm ci && npm run dev        # UI in a browser with a mock transport (synthetic input)
cd driver/test && make                 # host build + run of the C pipeline against the shared vectors
```

## Driver signing

### Why the installer asks to create a certificate

Windows installs a driver package only if its catalog (`openx3d.cat`, the list of hashes of the driver's files) is signed by a certificate the PC trusts. The driver runs in user mode (UMDF 2), so it does not need the Microsoft (WHQL or attestation) signature that kernel drivers require; any trusted code-signing certificate works.

Open X3D Pro does what [libwdi/Zadig](https://github.com/pbatard/libwdi/wiki/Certification-Practice-Statement) does: the catalog ships **unsigned** and is signed on your PC, by a certificate made on your PC, whose private key is then destroyed. The installer's first page has a checkbox, unticked by default. When it is ticked, [`sign-catalog.ps1`](driver/scripts/sign-catalog.ps1) runs elevated and:

1. Removes any certificate from an earlier Open X3D Pro install.
2. Creates a new self-signed code-signing certificate, `CN=Open X3D Pro local driver signing (key destroyed)`, with a non-exportable private key in the machine store (usable by administrators only).
3. Signs `openx3d.cat` with it.
4. Deletes the private key.
5. Only then adds the certificate (public part only) to the local machine's *Trusted Root Certification Authorities* store, which makes the signature valid, and its *Trusted Publishers* store, which stops Windows asking "Would you like to install this device software?". The key never exists while the certificate is trusted.

Then the driver is installed. Other cases:

- **Unticked:** only the app is installed and the stick keeps the stock Windows driver, so there are no curves or remapping in games. Run the installer again to change your mind.
- **Uninstall** removes the certificate from both stores.
- **Upgrades** remember the choice: the box starts ticked if the driver was installed before, and passive (`/P`) upgrades and silent `/UPDATE` installs keep the driver.
- **Other silent (`/S`) and passive (`/P`) installs** do this only when given `/TRUSTCERT`.

### What the certificate can and cannot do

Because the private key is deleted seconds after it is created, before the certificate is trusted, **nobody can sign anything with this certificate**: not an attacker, not malware, not the Open X3D Pro developers. Its only effect is that Windows accepts the one catalog it already signed. There is no project-wide driver key to steal, and each PC's certificate is different.

Its extensions limit it further, all marked critical so Windows enforces them:

| Extension | Value | Effect |
|---|---|---|
| Extended Key Usage | Code Signing (`1.3.6.1.5.5.7.3.3`) only | Windows rejects it for websites (TLS server or client), e-mail (S/MIME), document signing, smart-card logon and every other purpose. |
| Key Usage | Digital Signature only | It cannot be used to encrypt data or exchange keys. |
| Basic Constraints | `CA:FALSE` (end entity) | It cannot issue other certificates. Windows rejects any certificate chain that names it as the issuer. |

It also cannot sign kernel-mode drivers. With Secure Boot on, Windows 10 1607+ loads only kernel drivers signed by Microsoft, whatever is in the local stores.

### How to check

```powershell
# The certificate this PC trusts (expect one entry in Root and one in TrustedPublisher)
Get-ChildItem Cert:\LocalMachine\Root, Cert:\LocalMachine\TrustedPublisher |
  Where-Object Subject -like '*Open X3D Pro*' |
  Format-List PSParentPath, Subject, Thumbprint, NotAfter, HasPrivateKey, EnhancedKeyUsageList

# Its extensions: "End Entity", "Digital Signature", "Code Signing" and nothing else
certutil -store Root "Open X3D Pro local driver signing (key destroyed)"

# The private key is gone: this must print nothing
Get-ChildItem Cert:\CurrentUser\My, Cert:\LocalMachine\My | Where-Object Subject -like '*Open X3D Pro*'

# The catalog it signed, as installed in the driver store
Get-WindowsDriver -Online | Where-Object OriginalFileName -like '*\openx3d.inf' |
  ForEach-Object { Get-AuthenticodeSignature (Join-Path (Split-Path $_.OriginalFileName) openx3d.cat) } |
  Format-List Path, Status, SignerCertificate

# Remove it by hand (elevated); the driver stays installed until you uninstall it
Get-ChildItem Cert:\LocalMachine\Root, Cert:\LocalMachine\TrustedPublisher |
  Where-Object Subject -eq 'CN=Open X3D Pro local driver signing (key destroyed)' | Remove-Item
```

`HasPrivateKey` must be `False`.

### The installer and app

The setup exe, the app and the uninstaller are **not code-signed**. A self-signed certificate would change nothing for you: SmartScreen, UAC and Smart App Control treat it exactly like no signature. A certificate Windows trusts out of the box costs money every year. Instead, every download can be traced to the commit and CI run that built it (below).

### Provenance and attestation

- Nightlies and releases are built only by GitHub Actions from this repository: [`build.yml`](.github/workflows/build.yml), called by [`nightly.yml`](.github/workflows/nightly.yml) and [`release.yml`](.github/workflows/release.yml).
- On the Windows runner, CI runs `sign-catalog.ps1` on the exact files the installer ships. It checks that the signed catalog verifies and covers `openx3d.dll`, that the certificate has the extensions above, that no private key is left, and that `-Remove` cleans up.
- Each artifact carries `BUILD_INFO.txt` (commit, ref, build time, run URL) and `SHA256SUMS.txt`.
- Every file gets a [GitHub build-provenance attestation](https://docs.github.com/actions/security-for-github-actions/using-artifact-attestations) (SLSA provenance, signed through Sigstore with the workflow's OIDC identity). It proves the file was built from a specific commit of `kaysond/open-x3d-pro` by a specific workflow run. Verify it before running the installer:

  ```sh
  # A release: built from that tag by the release workflow
  gh attestation verify Open-X3D-Pro_0.1.0_x64-setup.exe --repo kaysond/open-x3d-pro \
    --source-ref refs/tags/v0.1.0 --signer-workflow kaysond/open-x3d-pro/.github/workflows/build.yml
  # A nightly: built from main (any branch can be built by hand, so pin the ref)
  gh attestation verify Open-X3D-Pro_0.1.0_x64-setup.exe --repo kaysond/open-x3d-pro \
    --source-ref refs/heads/main --signer-workflow kaysond/open-x3d-pro/.github/workflows/build.yml
  ```

  `--repo` alone accepts any attested build of the repository, including a manual run of a modified workflow on a branch.

  Without the GitHub CLI, compare the file's hash (`Get-FileHash` in PowerShell) with `SHA256SUMS.txt` and the release notes, and look the attestation up under the repository's **Attestations** page.

### Limits

- **Smart App Control** (Windows 11), when **on**, blocks the installer and the app, with no per-app override. It only accepts certificates from CAs in Microsoft's [Trusted Root Program](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control) and ignores roots added locally, and it checks every executable, not just downloads. It would very likely also block the locally signed driver DLL. Its *evaluation* mode blocks nothing, and it is off on most PCs. To use Open X3D Pro, turn it off in Windows Security, App & browser control; since the April 2026 update (KB5083769) it can be turned back on later.
- **SmartScreen and UAC:** the downloaded installer shows "Windows protected your PC" (choose "More info", then "Run anyway"), and UAC shows "Unknown publisher".
- Early nightlies (before 2026-10-05) used a throwaway certificate. Remove it with `certutil -delstore Root "Open X3D Pro (unsigned beta)"` and `certutil -delstore TrustedPublisher "Open X3D Pro (unsigned beta)"`.

## Privacy

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. The app makes no network connections and keeps its profiles in `%APPDATA%\OpenX3DPro`; only the installer may download the WebView2 bootstrapper from Microsoft if WebView2 is missing ([Microsoft Privacy Statement](https://privacy.microsoft.com/privacystatement)).
