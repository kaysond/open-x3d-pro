# Open X3D Pro

Open-source replacement for Logitech Gaming Software 5.10 for the Logitech Extreme 3D Pro joystick (`USB\VID_046D&PID_C215`) on Windows 10 22H2 and Windows 11 24H2/25H2 x64. It provides per-axis calibration, deadzones, response curves, inversion, button remapping, hat-as-buttons, a shift layer and per-application profiles applied automatically by a tray agent. It contains no kernel-mode code, so it installs and runs with Secure Boot, Memory Integrity (HVCI) and Smart App Control on, unlike LGS 5.10's 2010-era kernel filter.

**Status: pre-alpha.** Nothing here is ready for daily use yet.

## Architecture

- `driver/`: UMDF 2 HID minidriver (`openx3d.dll`) that replaces inbox `hidusb` as function driver of the stick; user mode only.
- It reads the 7-byte interrupt report, runs the axis/button pipeline inline and republishes two HID collections.
- Collection 1 is a joystick (4 × 16-bit axes, hat, 32 buttons) that games, joy.cpl and DirectInput see.
- Collection 2 is a vendor channel: raw input reports plus feature reports to load and query the active config.
- The config is a 240-byte CRC-checked blob, persisted in the device registry key and reloaded at device start.
- `core/`: Rust crate `x3d-core` with the config types, reference pipeline, blob compiler and test vector generator.
- Driver C and Rust pipelines agree bit-for-bit, checked against shared vectors in `core/testdata/vectors.json`.
- `app/`: Tauri v2 tray agent (Rust backend, React + TypeScript UI) that edits profiles and pushes them to the driver.
- Profiles switch on the foreground or running executable; the NSIS installer adds the driver via `pnputil`.
- Interfaces and layout: [docs/CONTRACT.md](docs/CONTRACT.md). Background and design rationale: [docs/research.md](docs/research.md).

## Building

Prerequisites:

- Rust stable (pinned via `rust-toolchain.toml`, with rustfmt and clippy)
- Node.js 20
- Windows Driver Kit: only needed to build the driver, which happens in CI on GitHub's Windows runners. Everything else builds and tests on Linux.

Dev commands:

```sh
cargo test --workspace                 # core + app backend (Win32 code is stubbed off Windows)
cd app && npm ci && npm run dev        # UI in a browser with a mock transport (synthetic input)
cd driver/test && make                 # host build + run of the C pipeline against the shared vectors
```

## Signing

All builds, nightlies (Actions artifacts from pushes to `main`) included, are code-signed by SignPath Foundation. The installer never modifies certificate stores; Windows asks once whether to install the driver from that publisher.

Early nightlies (before 2026-10-05) used a throwaway self-signed certificate that their installer added to the machine stores. If you installed one, remove it from an elevated prompt: `certutil -delstore Root "Open X3D Pro (unsigned beta)"` and `certutil -delstore TrustedPublisher "Open X3D Pro (unsigned beta)"`.

- Approvers: [@kaysond](https://github.com/kaysond)

Every build is signed with this certificate: the installer and driver built from this repository by GitHub Actions, for releases (`.github/workflows/release.yml`, `v*` tags, attached to GitHub Releases) and nightlies (`.github/workflows/nightly.yml`, pushes to `main`, workflow artifacts). Each signing request is approved manually.

Privacy policy: This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. The app makes no network connections and keeps its profiles in `%APPDATA%\OpenX3DPro`; only the installer may download the WebView2 bootstrapper from Microsoft if WebView2 is missing ([Microsoft Privacy Statement](https://privacy.microsoft.com/privacystatement)).
