# Open X3D Pro — component contract

Single source of truth for the interfaces between the four independently written parts of this monorepo. Every component must implement exactly what is written here; if something here is wrong or missing, change this file first, in the same PR, and say so in the commit message.

Repository: `github.com/kaysond/open-x3d-pro` (public, MIT). Device: Logitech Extreme 3D Pro, `USB\VID_046D&PID_C215` (user's unit `REV_0204`, USB 1.1 low-speed, 7-byte input report at 100 Hz, one 4-byte vendor feature report that the device stalls on GET_REPORT — never issue GET_REPORT/GET_FEATURE to the physical device).

Hard constraint: everything must install and run on Windows 10 22H2 and Windows 11 24H2/25H2 x64 with Secure Boot ON, Memory Integrity (HVCI) ON, Smart App Control default, TESTSIGNING off. Hence: **no kernel-mode code anywhere.** The driver is a UMDF 2 HID minidriver.

## 2. Driver architecture (option B from the research)

UMDF 2 HID minidriver that **replaces the inbox `hidusb` as the function driver of `USB\VID_046D&PID_C215`**, modelled on Nefarius DsHidMini and Microsoft's `hid/vhidmini2` UMDF sample:

- INF `Class=HIDClass`, `ClassGuid={745a17a0-74d3-11d0-b6fe-00a0c90f57da}`, `Provider=%Mfg%`, `CatalogFile=openx3d.cat`, `DriverVer` from build. Models (NTamd64 only): `USB\VID_046D&PID_C215&REV_0204` and `USB\VID_046D&PID_C215`, same install section (rank 0x00FF0000 / 0x00FF0001 beats inbox 0x00FF2005 on Win11, 0x00FF0001 LGS on Win10).
- Services: `mshidumdf` as the device service (`AddService=mshidumdf,0x2,...` / Win11 `Include=MsHidUmdf.inf, Needs=MsHidUmdf.NT`), `WUDFRd` as lower filter (Win10: `HKR,,LowerFilters,0x10000,WUDFRd` in `.NT.hw` + explicit `AddService=WUDFRd`; Win11: `Needs=WUDFRD_LowerFilter.NT*` incl. `.NT.Filters`, as vhidmini2). Win10 (`.NTamd64.10.0...19041`) and Win11 (`.NTamd64.10.0...22000`) decorated sections as DsHidMini does. DLL runs from the driver store (`DestinationDirs` DIRID 13, `ServiceBinary=%13%\openx3d.dll`; InfVerif `/w` rejects `12,UMDF`). The Win10 branch cannot be `/w`-clean (inbox `ServiceBinary=%12%\…` → 2084, AddReg filters → 1329) because `MsHidUmdf.inf` only exists from build 22000; validate with `InfVerif /v /h` (or `/w /wbuild 10.0.22000`).
- `[*.Wdf]`: `UmdfService=openx3d,openx3d_Install`, `UmdfServiceOrder=openx3d`, `UmdfDispatcher=NativeUSB`, `UmdfKernelModeClientPolicy=AllowKernelModeClients`, `UmdfFileObjectPolicy=AllowNullAndUnknownFileObjects`, `UmdfFsContextUsePolicy=CanUseFsContext2`, `UmdfLibraryVersion=2.15.0`, `UmdfMethodNeitherAction=Copy`, `UmdfHostPriority=PriorityHigh` (as DsHidMini). Build with `UMDF_VERSION_MAJOR=2`, `UMDF_VERSION_MINOR=15`.
- USB: `WdfUsbTargetDeviceCreate` (the UMDF fx2 sample only uses `…CreateWithParameters`/`USBD_CLIENT_CONTRACT_VERSION_602` from UMDF 2.25; it buys nothing for a low-speed HID device), select config 0 / interface 0, continuous reader on interrupt-IN pipe `0x81` (7 bytes). Never send class requests to the device.
- Report processing: on every USB report run `pipeline_process()` (see §4) → complete up to two pending `IOCTL_HID_READ_REPORT` (one manual queue per device; hidclass routes by report ID): first report ID 1 (joystick), then report ID 2 (vendor raw). With only one pending read it gets ID 1, unless the last completion was ID 1 and ID 2 has not been sent for 100 ms. Keep last reports to answer `IOCTL_HID_GET_INPUT_REPORT` synchronously (DirectInput polls this).
- Must implement: `IOCTL_HID_GET_DEVICE_DESCRIPTOR`, `GET_REPORT_DESCRIPTOR`, `GET_DEVICE_ATTRIBUTES` (VID/PID/bcdDevice taken from the real USB device descriptor), `GET_STRING`/`GET_INDEXED_STRING` (manufacturer "Logitech", product "Logitech Extreme 3D Pro (Open X3D)"), `READ_REPORT`, `GET_INPUT_REPORT`, `SET_FEATURE`, `GET_FEATURE`, `WRITE_REPORT`/`SET_OUTPUT_REPORT` (return `STATUS_NOT_SUPPORTED`), `ACTIVATE/DEACTIVATE_DEVICE` (success), `SEND_IDLE_NOTIFICATION_REQUEST` (`STATUS_NOT_IMPLEMENTED`, as vhidmini2 and DMF VirtualHidMini: we never invoke the idle callback, so success could stall hidclass). Use the `vhidmini2` UMDF pattern (`IOCTL_UMDF_HID_*` variants carry the buffer differently — handle both as that sample does).
- Config persistence: on `SET_FEATURE` report 3 → validate (magic, version, size, CRC32) → apply atomically → write `REG_BINARY` value `Config` under the driver's subkey of the device hardware key (`WdfDeviceOpenRegistryKey(PLUGPLAY_REGKEY_DEVICE | WDF_REGKEY_DEVICE_SUBKEY, KEY_READ | KEY_SET_VALUE)`; UMDF may only read the hardware key itself). If the write fails the config is still applied and flag bit0 is cleared. On device start read it back; if absent/invalid use the identity config (§4.3).
- Latency: process inline in the continuous-reader callback; no timers, no extra threads.

### 2.1 HID report descriptor published by the driver (two top-level collections)

**Collection 1 — Joystick** (`Usage Page 0x01, Usage 0x04 Joystick`, Application), **report ID 1**, 14 bytes incl. ID:

| Field | Usage | Size | Logical | Notes |
|---|---|---|---|---|
| X | 0x01:0x30 | 16 | 0..65535 | centre 32768 |
| Y | 0x01:0x31 | 16 | 0..65535 | |
| Rz | 0x01:0x35 | 16 | 0..65535 | twist |
| Slider | 0x01:0x36 | 16 | 0..65535 | throttle |
| Hat | 0x01:0x39 | 4 | 0..7, Null State, Physical 0..315, Unit 0x14 | 8 = centred |
| pad | const | 4 | | |
| Buttons 1–32 | 0x09:0x01..0x20 | 32×1 | 0..1 | |

**Collection 2 — Vendor** (`Usage Page 0xFF00, Usage 0x01`, Application):

- **Input report ID 2** (11 bytes incl. ID): `u8 raw[7]` (the untouched device report), `u16 seq` (wraps), `u8 flags` (bit0 = config loaded from registry, bit1 = config is identity).
- **Feature report ID 3** (256 bytes incl. ID), SET and GET: `u8 data[255]` = the config blob (§4.2) zero-padded. GET returns the active blob.
- **Feature report ID 4** (32 bytes incl. ID), GET only: `u16 driver_version_bcd` (0x0010 = 0.1.0), `u16 bcdDevice`, `u32 active_config_crc32`, `u8 raw_last[7]`, `u8 state` (same flags as above), rest zero.

Exact descriptor bytes are generated by the driver agent; the Rust crate must contain an identical copy as `x3d_core::hid::REPORT_DESCRIPTOR` with a test asserting it parses (use the `hidparser`-free approach: hand-check length and a few offsets; no extra crate needed) so the two stay in sync.

hidclass will enumerate `HID\VID_046D&PID_C215&Col01` (games, joy.cpl, inbox `hidgamepad`/`HID_Raw_Inst` bind as today) and `HID\VID_046D&PID_C215&Col02` (opened by the app via `hid.dll`).

## 3. Profiles and configuration (JSON, shared by backend and frontend)

TypeScript type names == Rust struct names (serde, `rename_all = "camelCase"`). Profiles live in `%APPDATA%\OpenX3DPro\profiles\<id>.json`; settings in `%APPDATA%\OpenX3DPro\settings.json`.

```ts
type AxisId = 'x' | 'y' | 'rz' | 'slider';

interface Calibration { min: number; center: number; max: number }     // raw units 0..65535 (device raw scaled: 10-bit<<6, 8-bit<<8)
interface Deadzone    { center: number; min: number; max: number }     // fractions 0..0.5 of half-range (center) / of range ends (min/max)
type Curve =
  | { type: 'linear' }
  | { type: 'exponent'; exponent: number }          // 0.2..5; y = x^exponent on normalized magnitude
  | { type: 'points'; points: [number, number][] }  // 2..17 points, x strictly increasing in [0,1], y in [0,1]; piecewise-linear
interface AxisConfig {
  calibration: Calibration;
  invert: boolean;
  deadzone: Deadzone;
  curve: Curve;
  sensitivity: number;          // gain 0.1..4.0 applied after curve, output clamped
  curveMode: 'symmetric' | 'full';   // symmetric about center (X/Y/Rz default) or full range 0..1 (slider default)
  target: AxisId | null;        // which output axis receives this physical axis; null = disabled; default = itself
}
type HatMode = 'hat' | 'buttons' | 'both';           // buttons: U,R,D,L -> output buttons 13,14,15,16 (diagonals set two)
interface ButtonBinding { output: number | null }   // output button 1..32, null = none
interface KeyBinding { button: number; keys: string[] }  // physical button 1..12 -> keyboard chord as DOM KeyboardEvent.code names in press order, e.g. ["ControlLeft","KeyF"]; emitted by the backend via SendInput (LGS-style), not by the driver
interface DeviceConfig {
  axes: Record<AxisId, AxisConfig>;
  hatMode: HatMode;
  buttons: ButtonBinding[];         // length 12, index = physical button-1
  shiftButton: number | null;       // physical button 1..12 acting as momentary shift; emits nothing itself unless also mapped
  buttonsShifted: ButtonBinding[];  // length 12, used while shift held
  keyBindings: KeyBinding[];
}
interface Profile {
  id: string;            // uuid v4
  name: string;
  exePaths: string[];    // full paths or bare exe names, case-insensitive match
  isDefault: boolean;    // exactly one profile is default; applied when no exe matches
  config: DeviceConfig;
}
interface Settings { autostart: boolean; switchingPaused: boolean; matchMode: 'foreground' | 'running' }
```

`DeviceConfig.default()` = identity: calibration {0, 32768, 65535} per axis (slider {0,0,65535}), no inversion, zero deadzones, linear curve, sensitivity 1, symmetric for x/y/rz and full for slider, target = self, hatMode 'hat', buttons i→i, shiftButton null, buttonsShifted all null, no key bindings. `Settings` default: autostart true, switchingPaused false, matchMode 'foreground'.

Backend validation (`save_profile`/`preview_config` return an error otherwise): symmetric axes need `min < center < max`, full axes `min < max`; deadzones each 0..0.5 and, after rounding to permille, every pair (center+min, center+max, min+max) < 1000; sensitivity 0.1..4; exponent 0.2..5; points as typed above; outputs 1..32; shift/key-binding buttons 1..12; key names must be known `KeyboardEvent.code` values.

## 4. Pipeline and config blob (driver C and Rust must agree bit-for-bit)

### 4.1 Processing per physical axis
1. `raw16`: X,Y 10-bit → `raw << 6`; Rz, Slider 8-bit → `raw << 8`.
2. Calibrate. Symmetric mode: `v = raw16 <= center ? -(center-raw16)/(center-min) : (raw16-center)/(max-center)`, clamp to [-1,1]. Full mode: `v = (raw16-min)/(max-min)`, clamp [0,1].
3. Invert: symmetric `v = -v`; full `v = 1-v`.
4. Deadzones with rescale. Symmetric: `m = |v|; m = m <= dzc ? 0 : (m - dzc)/(1 - dzc - dzEnd)`, where `dzEnd = sign(v) < 0 ? dzMin : dzMax`; clamp [0,1]. Full: `v = (v - dzMin)/(1 - dzMin - dzMax)`, clamp [0,1].
5. Curve via 17-point LUT: `lut[i]` = output for input `i/16`, u16 0..65535; linear interpolation between points. LUT is built by the compiler from `Curve` and `sensitivity` (gain multiplied in, clamped to 65535). Identity LUT = `round(i * 65535 / 16)`.
6. Output. Symmetric: `out = 32768 + sign(v) * lutval/2` → clamp 0..65535 (so +1 → 65535, −1 → 1; centre exactly 32768). Full: `out = lutval`.
7. Write `out` to `target` axis slot; disabled axes output 32768 (symmetric) / 0 (full); if two physical axes target one output the higher physical index wins. Precisely: output slot `s` starts at 32768, or 0 if `axes[s].mode` is full; then physical axes 0..3 with `target != 0xFF` write their slot in that order.

Hat: raw 0..7 passes through in 'hat'/'both', 8 in 'buttons'; buttons 13–16 set per direction in 'buttons'/'both'. Buttons: `shift = shiftButton != 0 && raw_button[shiftButton]`; for each physical i: `out = shift ? buttonsShifted[i] : buttons[i]`; if `out != 0` set bit `out-1`. A physical button mapped to nothing is dropped.

Integer implementation in the driver is fine (Q16 fixed point) as long as results match the Rust float reference within ±1 LSB of u16 output; the test vectors allow ±1.

### 4.2 Blob (`X3D_CONFIG`, little-endian, `#pragma pack(1)`, 240 bytes total)

```
offset size field
0      4    magic = "X3DP" (0x50443358 LE)
4      2    version = 1
6      2    size = 240
8      4    crc32 (IEEE 802.3, over bytes 12..239)
12     4×50 axes[4] in order X, Y, Rz, Slider:
            u16 cal_min, u16 cal_center, u16 cal_max,
            u16 dz_center_permille, u16 dz_min_permille, u16 dz_max_permille,   // 0..500
            u8  invert (0/1), u8 mode (0 = symmetric, 1 = full), u8 target (0..3 or 0xFF = disabled), u8 reserved,
            u16 lut[17]
212    1    hat_mode (0 hat, 1 buttons, 2 both)
213    1    shift_button (0 none, 1..12)
214    12   button_map[12]      (0 none, 1..32)
226    12   button_map_shift[12]
238    2    reserved = 0
```

`x3d_core::blob::compile(&DeviceConfig) -> [u8; 240]` and `x3d_core::blob::parse(&[u8]) -> Result<DeviceConfig-ish view>`; the driver (`driver/pipeline/pipeline.h`) has `bool pipeline_validate(const uint8_t *blob, size_t len)` (magic, version, size, CRC), `void pipeline_identity(X3D_CONFIG *out)`, `void pipeline_process(const X3D_CONFIG *cfg, const uint8_t raw[7], X3D_JOY_REPORT *out)` and `uint32_t pipeline_crc32(const void *, size_t)`. In symmetric mode a magnitude inside the centre deadzone outputs exactly 32768 (sign counts as 0), matching the Rust reference.

### 4.3 Test vectors

`core/testdata/vectors.json`: array of `{ "name", "blob": hex string (240 bytes), "cases": [ { "raw": hex 7 bytes, "x","y","rz","slider": u16, "hat": u8, "buttons": u32 } ] }` covering: identity, inversion, each deadzone, exponent 0.5 and 2.0, a 5-point curve, sensitivity 2.0 clamp, swapped targets, disabled axis, hat modes, shift layer, button drop. Driver host test loads the same file and asserts ±1 on axes, exact on hat/buttons.

## 5. Backend ⇄ frontend IPC (Tauri v2 commands and events)

All commands return `Result<T, String>`; errors are human-readable. Payloads are the §3 types.

| Command | Args | Returns |
|---|---|---|
| `get_state` | — | `AppState { deviceConnected: boolean; driverInstalled: boolean; driverVersion: string \| null; activeProfileId: string \| null; matchedExe: string \| null; settings: Settings }` |
| `list_profiles` | — | `Profile[]` |
| `save_profile` | `profile: Profile` | `Profile` (creates if id unknown or empty; ids are `[A-Za-z0-9_-]{1,64}`, new ones uuid v4) |
| `delete_profile` | `id: string` | `void` (refuses to delete the default) |
| `set_default_profile` | `id: string` | `void` |

| `preview_config` | `config: DeviceConfig` | `void` — push to driver immediately without saving (live editing); automatic switching suppressed until `activate_profile(null)` or profile saved |
| `list_windows` | — | `WindowInfo[] { pid: number; exePath: string; title: string }` (visible top-level windows, for "add running app") |

| `start_calibration` / `finish_calibration` | `axis: AxisId` / `axis: AxisId` | `void` / `Calibration` (backend tracks min/max while running, center = value at finish) |
| `export_profile` / `import_profile` | `id` / `json: string` | `string` (JSON) / `Profile` |

Events (`app.emit`):

| Event | Payload | Rate |
|---|---|---|
| `input` | `InputFrame { raw: { x: number; y: number; rz: number; slider: number; hat: number; buttons: number }, processed: { x; y; rz; slider; hat; buttons }, seq: number }` raw in device units (10/8-bit, hat 0..8, 12-bit button mask); processed in u16/hat/32-bit mask | every device report, coalesced to ≤ 60 Hz for the UI |
| `state` | `AppState` | on change |
| `profile_switched` | `{ profileId: string; exePath: string \| null; reason: 'foreground' \| 'running' \| 'manual' \| 'default' }` | on change |

When the driver is **not** installed (dev, or milestone 0) the backend reads the inbox 7-byte reports and computes `processed` itself with `x3d_core::pipeline`, so the whole UI works against the stock driver; `driverInstalled=false` and `preview_config` only affects the in-app processed view.

## 6. Backend behaviour

- Single instance (`tauri-plugin-single-instance`); starts hidden in the tray; window on tray click / "Open"; closing the window hides it; "Quit" exits. Tray tooltip shows active profile. Menu: Open, active profile name (disabled item), Pause switching (checkbox), Quit.
- Autostart via `tauri-plugin-autostart` (HKCU Run), argument `--minimized`.
- Device access via `hidapi` crate (`windows-native` feature, no C): open `Col02` by VID/PID/usage page 0xFF00 for raw input + feature reports; open `Col01` (usage page 1 usage 4) for processed input. Reconnect loop on unplug (poll every 1 s).
- Profile switching: `SetWinEventHook(EVENT_SYSTEM_FOREGROUND … WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS)` on the main thread → `GetWindowThreadProcessId` → `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` → `QueryFullProcessImageNameW`; debounce 250 ms; match full path (case-insensitive) then basename; `matchMode: 'running'` instead scans processes every 2 s (`CreateToolhelp32Snapshot`) and keeps the matched profile while the process lives. No match → default profile. Push = `HidD_SetFeature` of the compiled blob via hidapi `send_feature_report` (report ID 3) only when the blob CRC differs from the last pushed.
- Key bindings: on processed button edge (raw physical button), send chords via `SendInput` (scan codes), release on button up. Skip when no bindings.
- All Win32-specific code behind `#[cfg(windows)]` with no-op stubs on other OSes so `cargo check`, `cargo clippy` and `cargo test` pass on Linux (that is what CI's fast lane and the dev box run).
- Installer: Tauri NSIS bundle, `installMode: perMachine`, `webviewInstallMode: downloadBootstrapper`; `bundle.resources` includes `resources/driver/**` (openx3d.inf, openx3d.dll, openx3d.cat, openx3d.cer); `windows/hooks.nsh` implements `NSIS_HOOK_POSTINSTALL`: only when the build staged `self-signed.flag` (nightlies) `certutil -addstore -f Root` + `TrustedPublisher` with `openx3d.cer`; CA-signed releases touch no certificate store and rely on Windows' one-time publisher prompt (CN for nightly uninstall comes from `cert-cn.txt`), `pnputil /add-driver "$INSTDIR\resources\driver\openx3d.inf" /install`; `NSIS_HOOK_PREUNINSTALL`: `pnputil /delete-driver openx3d.inf /uninstall /force`, falling back to `Get-WindowsDriver -Online` (locale-independent, unlike `pnputil /enum-drivers` text) to find the published `oemN.inf`, then `certutil -delstore Root|TrustedPublisher "Open X3D Pro (unsigned beta)"` (the CN from §8). The NSIS stub is 32-bit, so tools are run from `$WINDIR\Sysnative`. Log pnputil exit code; 259/3010 = success needing reboot.

## 7. Frontend

React 18 + TypeScript + Vite (Tauri's documented pairing; no Next.js — no routing/SSR need). State: zustand. Styling: plain CSS modules or Tailwind — pick one, keep it light. Pages (simple tabs): **Test** (live raw vs processed: axis bars with both values, hat rose, 12 physical + 32 output button grid, seq/Hz counter), **Axes** (per-axis tab: calibration wizard using `start/finish_calibration`, deadzone sliders, invert, sensitivity, curve mode, curve editor canvas — exponent knob or draggable points, live marker from `input`, reset to linear), **Buttons** (12 physical → output 1..32 dropdowns, shift button select, shifted layer, hat mode, key bindings capture), **Profiles** (list, default badge, active indicator, create/duplicate/delete, exe paths with "Add running app…" using `list_windows`, import/export), **Settings** (autostart, match mode, pause, driver status/version). Edits call `preview_config` live (debounced 50 ms) and "Save" persists. `src/lib/ipc.ts` wraps every command/event with the §3/§5 types. Mock transport when `window.__TAURI_INTERNALS__` is absent (synthetic input at 60 Hz, in-memory profiles) so `npm run dev` works in a browser on the Linux dev box.

Artifact configurations (product name/version metadata restrictions required by SignPath Foundation) and portal setup: `.github/signpath/`.
  - Both: stage `openx3d.inf/.dll/.cat/.cer` into `app/src-tauri/resources/driver/`, plus `cert-cn.txt` (certificate CN, UTF-16LE) and, for self-signed builds only, empty `self-signed.flag` → installer from the ROOT workspace `target/release/bundle/nsis/` (located via `cargo metadata`) → `signtool verify /pa` on setup exe, DLL, catalog → artifact `<prefix>-<sha7>` (14 days): `Open-X3D-Pro_<ver>_x64-setup.exe`, `openx3d-driver-<ver>.zip` (inf, dll, cat, cer, install.ps1, uninstall.ps1), `openx3d.cer`, `BUILD_INFO.txt` (sha, ref, UTC time, run URL, signer), `SHA256SUMS.txt`. The version is never altered; nightlies are identified by sha.
- `hooks.nsh` certificate policy: certificate stores are touched only when `resources/driver/self-signed.flag` exists (nightlies: `Root` + `TrustedPublisher`, removed on uninstall by the CN in `cert-cn.txt`). CA-signed releases (SignPath Foundation) import nothing — the certificate is shared with other publishers, so Windows' one-time "install this device software?" prompt is the trust boundary.
- `nightly.yml` on push to `main` + `workflow_dispatch` (any branch), `concurrency: nightly-<ref>` with cancel-in-progress: `build.yml` with `signing: self-signed`, artifact `open-x3d-pro-nightly-<sha7>`. No tags, no GitHub Release.
- `release.yml` on tags `v*`: `check` (ubuntu-24.04) fails fast unless secrets `SIGNPATH_API_TOKEN` and `SIGNPATH_ORGANIZATION_ID` are set (no self-signed fallback), then requires the tag to equal the version in `tauri.conf.json`, `app/package.json`, root `Cargo.toml` `[workspace.package]`, the INF `DriverVer` (first three components) and `openx3d.rc` `ProductVersion` (`a.b.c.0`, the SignPath `driver` metadata restriction) → `build.yml` with `signing: signpath` (secrets passed explicitly; the run waits for both manual approvals) → `publish` (only job with `contents: write`): GitHub Release (`softprops/action-gh-release@v3`, auto notes + fixed header incl. the "Code signing policy" link SignPath Foundation requires on release pages, prerelease while `v0.*` or suffixed) with every file of the artifact.
